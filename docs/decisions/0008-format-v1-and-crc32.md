# 0008: Format version 1, CRC-32 and rejecting version 0

- **Date:** 2026-10-13
- **Milestone:** M6
- **Status:** Accepted

## Context

Version 0 had no checksum. Measured by flipping every bit of a 3.6 KB file one at a time and decoding with tcomp 0.5, **48% (LZH) to 80% (HUFFMAN) of single-bit flips decoded "successfully" to wrong data**, and every truncation of a STORE file was accepted (full table in [BENCHMARKS.md](../BENCHMARKS.md#m6-format-v1-and-crc-32)). A compressor that can silently return wrong bytes isn't trustworthy, whatever its ratio. M6 fixes the format before calling it 1.0.

## Options considered

**Which checksum**

1. **Adler-32** (zlib's stream checksum). Very fast and simple, but weak on short inputs: its sums have barely moved after a few hundred bytes.
2. **CRC-32** (polynomial 0xEDB88320, as in gzip, zip and PNG). Detects every error burst of up to 32 bits, and other damage with probability 1 − 2⁻³². Standard, so results can be cross-checked against Python's `zlib.crc32`.
3. **CRC-32C** (Castagnoli). Same strength, and x86 and ARM have an instruction for it. That instruction needs platform-specific code, and with a portable table the speed is the same as CRC-32.
4. **xxHash, or a cryptographic hash (SHA-256).** xxHash is faster but makes no guarantee about bursts. SHA-256 protects against deliberate tampering, which isn't the threat here, and is several times slower without dedicated CPU instructions.

**How to compute CRC-32** (measured on 64 MB, same machine):

| Method | Speed | Note |
| --- | ---: | --- |
| Bit at a time | 97 MB/s | The definition; 8 shift/XOR steps per byte |
| One table, byte at a time | 387 MB/s | 1 KB table; each step waits for the previous one |
| **Slicing-by-8** | **2,105 MB/s** | 8 KB of tables; 8 independent lookups per 8 bytes |

At LZH's ~110 MB/s decompression, byte-at-a-time would add about 28% to decompression time; slicing-by-8 adds about 5%.

**What the CRC covers**

1. **The compressed bytes.** `verify` could check a file without decoding it, but bugs in the encoder or decoder would go unnoticed.
2. **The original data.** End to end: it checks the whole pipeline, compressor bugs included, which is what the user actually cares about.

**Where size and CRC go**

1. **Both in the header.** The encoder must know the CRC before writing anything, which rules out streaming.
2. **Both in a trailer** (gzip's choice). Streams naturally, but the decoder can't bound its output before decoding, and `info` must read to the end of the file.
3. **Size in the header, CRC in a trailer.** The size lets the decoder reject impossible files before writing a byte (as M2–M5 already do) and lets `info` report it. The CRC is computed while writing, so streaming encoders (M7) can produce it at the end.

**Reading version 0 files**

1. **Keep reading them.** It looked like the friendly choice until we tested it: flipping the low bit of a v1 STORE file's version byte (1 → 0) produces a valid v0 STORE file. tcomp 0.5 decodes it with exit code 0, and the output has 9 extra bytes at the start (the flags and size fields) and 4 at the end (the CRC). A v0 file has nothing to check, so any decoder that accepts v0 can be fooled by one flipped bit.
2. **Reject them.** Version 0 was a development format with no stability promise, and anyone who has v0 files can decode them with tcomp 0.5 (tag `v0.5-deflate`).

## Decision

- **CRC-32 (IEEE) of the original data, slicing-by-8**, stored little-endian in a **4-byte trailer**. The tables are generated by `tools/gen-crc32-table.py` and committed. Unit tests recompute every result with the bit-at-a-time definition, so a wrong table entry can't go unnoticed, and no table has to be built at run time (which would need locking once threads arrive in M9).
- **Header: magic, version 1, method, a flags byte, the original size as a uint64** (15 bytes; 19 bytes of overhead with the trailer).
- **The flags byte must be 0.** It reserves room for M7 (for example a "size unknown" flag for pipes) without a version bump. Decoders reject flags they don't know, so an old decoder refuses a new file rather than misreading it.
- **Decoders accept exactly version 1.** Version 0 is rejected as "unsupported format version".
- **Structural errors are reported before checksum errors.** Each decoder still validates as it goes. "Checksum mismatch" means the file decoded cleanly but to different data.
- **No header checksum.** Every header field is either validated (magic, version, method, flags) or cross-checked by the CRC: a wrong size field changes the length of the output, and so its CRC. The exhaustive bit-flip test covers header bits too.
- **New commands:** `tcomp verify` decodes fully and checks the CRC without writing output (like `gzip -t`); `tcomp info` reads the header and trailer without decoding.

## Consequences

- Every single-bit flip and every truncation of the test files, in every method, is now rejected or decodes to the exact original. A unit test checks this exhaustively on every `make test`.
- Measured cost: the CRC is **4.0% of the instructions** executed by LZH decompression and 2.1% for HUFFMAN (callgrind, `bible.txt`), and in cache simulation it misses L1 only once per 64-byte line of data. Wall-clock benchmarks on the shared 2-vCPU test VM show decompression 10–17% slower than tcomp 0.5 when output is written, but no measurable difference when it is discarded (`verify`). Instruction counts and simulated caches don't explain that gap, so it should be re-measured on dedicated hardware.
- STORE compression now reads its whole input into memory (the header needs the size first), like every other method. M7's blocks remove this for all methods.
- On failure the CLI deletes the output file. When writing to stdout, data already written can't be taken back; the exit code (1) and the message say it is invalid. gzip behaves the same way.
- Breaking change: files written by tcomp 0.x can't be read by 1.0.
- Future versions should keep reading version 1. That is safe, unlike reading version 0, because every v1 file carries a CRC. The golden files in `tests/fixtures/v1/` enforce it.
